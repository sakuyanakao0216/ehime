# privacy-check

## このスキルが解決すること

プロトでも個人情報を扱うと、ログ垂れ流し・無期限保存・削除手段なし、が地雷になる。公開/ピッチ前に**データの取り扱い**を点検する。

1. **PII の収集・保存・表示**: 何を集め、どこに置き、誰に見せるか
2. **ログ**: PII/機密がログ・エラー・分析に漏れていないか
3. **外部送信**: 外部 API / AI プロバイダに送るデータ
4. **保存期間・削除**: いつ消すか、ユーザーが削除できるか

## 起動方法

### slash command
`/privacy-check [pii|logs|egress|retention]` で起動。

### 自律起動
「個人情報の扱いを確認」「ログに PII 出てない?」「保存期間と削除方針」などで自動起動。

## 点検観点（[privacy-checklist.md](./references/privacy-checklist.md)）

ユーザーがコード片やファイルを渡して「報告して」と依頼した場合は、追加質問せず、読み取れる範囲で結論を出す。回答には **PII** / **ログ** / **外部送信** / **保存期間** / **削除方針** の見出しを必ず含め、致命的 / 重要 / 望ましい の優先度で対策を書く。簡潔でよいが、**各指摘は検証・修正に着手できる具体性**を満たすこと:

- **検出根拠を必ず併記**: 該当ファイル名と行(または引用したコード断片)を指摘ごとに示す。「PII の懸念あり」だけで箇所を示さないのは不可。
- **対策は実装レベル**: マスク/ハッシュ/同意取得などの方向性だけでなく、修正後のコード例か具体的な設定を添える。
- **保存期間・削除方針は数値と実装まで**: 「触れる」で終わらせず、推奨 TTL(具体的な日数)と削除の実装方針(物理/論理削除・どの API/フラグで消すか)を書く。入力に保存先が無ければ `(要確認)` を明記したうえで推奨値を提示する。

| 観点 | 確認 |
|---|---|
| PII | 収集項目は必要最小限か / 表示は権限内か（auth-rules） |
| ログ | `console.log`/エラー/分析に PII を出していないか（deploy-preflight の console スキャンと連携） |
| 外部送信 | AI プロバイダ・外部 API・分析(GA等)に PII を送っていないか（analytics-events と連携） |
| 保存期間 | 不要に無期限保存していないか / TTL |
| 削除方針 | ユーザーがデータ削除を要求できるか / 物理 or 論理削除 |

## やってはいけないこと

- 同意なく PII を分析/AI に送る
- エラーログに生の PII を残す
- 「あとで考える」で削除手段を未設計のまま公開

## 周辺

- `ai-safety-check`: AI 出力固有の PII/安全性（こちらは AI 出力面）
- `analytics-events`: 計測に PII を含めない設計
- `firebase-backend`(auth-rules): 表示・アクセスの権限制御
- `deploy-preflight`: ログ/secret スキャンで一部を機械検出
