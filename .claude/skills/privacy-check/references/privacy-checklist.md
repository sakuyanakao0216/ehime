# プライバシー チェックリスト

各項目を OK / 要対応（致命/重要/望ましい）で判定し根拠を残す。プロト段階でも最低限の地雷は踏まない。

## 1. 収集（PII）
- [ ] 収集項目は目的に対し最小限（不要な生年月日・住所を集めていない）
- [ ] 取得時に利用目的が分かる（プライバシー方針/同意）
- [ ] 子ども・センシティブ情報（医療/信条等）の特別扱い

## 2. 保存・表示
- [ ] PII の保存場所を把握（Firestore コレクション / Storage）
- [ ] 表示は権限内のみ（auth-rules / Security Rules）
- [ ] 暗号化が必要な項目の検討（パスワードはハッシュ、Firebase Auth に委譲）

## 3. ログ
- [ ] `console.log`/サーバーログに PII を出していない
- [ ] エラー監視（Sentry 等）に PII が送られていない（observability-setup と連携）
- [ ] アクセスログの保持と範囲

## 4. 外部送信
- [ ] AI プロバイダに PII/機密を送っていない（ai-safety-check egress と連携）
- [ ] 分析(GA/PostHog)に PII を含めていない（analytics-events と連携）
- [ ] 第三者 API への送信内容と契約

## 5. 保存期間・削除
- [ ] 保存期間（TTL）を定義（無期限を避ける）
- [ ] ユーザーがデータ削除を要求できる手段
- [ ] 削除は論理 or 物理かを定義、関連データの波及（注文・ログ）
- [ ] アカウント削除時のフロー

## 出力フォーマット

```
## privacy-check レポート
### 致命的
- [logs] エラーログにメールアドレス → マスキング
### 重要
- [retention] ログ無期限 → 90日TTL
### 望ましい
- [collect] 任意項目の必須化を見直し
```

> 法令（個人情報保護法 / GDPR 等）の要件は管轄・最新で確認すること。本チェックは設計の抜け漏れ防止が目的で、法的助言ではない。
