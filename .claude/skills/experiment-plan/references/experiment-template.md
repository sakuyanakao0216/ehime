# 実験計画テンプレート

`docs/experiments/<name>.md` の雛形。

```markdown
# 実験: <名前>

## 仮説
- <変更> をすると <指標> が <方向> になる。なぜなら <理由>。

## 変更（バリアント）
- A（コントロール）: 現行
- B（処置）: <変更内容>

## 指標
| 種別 | 指標 | 計測イベント (analytics-events) |
|---|---|---|
| 主要 | sign_up 率 | `sign_up` / `page_view` |
| ガードレール | 直帰率 / エラー率 | `error_shown` |

## 判定基準
- 採用: B の主要指標が A を <閾値> 上回り、ガードレール悪化なし
- 棄却: 上回らない or ガードレール悪化
- 期間/サンプル: <期間 or 必要サンプル数>

## 対象
- <全ユーザー / 新規のみ / 特定セグメント>

## 出し分け方法
- feature flag（env or 単純な乱数割当）。プロトは軽量実装で可

## 結果（実施後に追記）
- 主要: A x% / B y% → 採用/棄却
- 学び: …
```

## 指針

- **1 実験 1 変更**（交絡を避ける）
- ガードレール指標を必ず置く（局所最適で全体悪化を防ぐ）
- プロトは厳密な統計検定より方向性。トラフィックが少ない前提を明記
- 割当の乱数は再現性のためシード/ユーザーIDハッシュで（`Math.random` の生使用を避ける）

> 統計的厳密性が要る場合は専用ツール（PostHog Experiments 等）を検討。最新仕様を確認すること。
