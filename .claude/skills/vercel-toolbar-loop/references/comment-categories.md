# Toolbar コメント 4 分類

`vercel-toolbar-loop` がコメント本文を分類するときの判定基準。

## (1) 視覚的修正 — 自動修正可

例:
- 「色を見やすく変える」「背景色を青にする」「もっと余白を」「文字を大きく」
- 「ボーダーを目立たせる」「角丸を強めに」

対応:
- `bg-*` / `text-*` / `p-*` / `m-*` / `border-*` / `rounded-*` クラスの差し替え
- CSS 変数 (`--primary`, `--accent` 等) のトークン置換が望ましい場合は `app/globals.css` を編集
- ハードコード hex は使わない (CLAUDE.md 規約)

判定キーワード: 色 / 余白 / 大きさ / フォント / 太さ / 影 / 角丸 / 配置

## (2) 文言修正 — 自動修正可

例:
- 「タイトルを "ダッシュボード" に」「ボタンの文言を "保存" に」
- 「コピーが固い、もう少し柔らかく」「typo: "ダウンンロード" を直して」

対応:
- 該当 JSX のテキストノードを Edit で置換
- i18n を使っているプロジェクトでは locale ファイル側を編集

判定キーワード: 文言 / コピー / タイトル / typo / 誤字 / 言い回し

## (3) 機能追加要望 — 自動修正しない (タスク化)

例:
- 「ここに検索機能を追加」「フィルタを増やしてほしい」「ソート機能が欲しい」
- 「グラフをもう 1 種類」「エクスポート機能」

対応:
- このスレッドは resolved にしない
- ユーザに「これは機能追加なので別タスクで対応する案件です。Issue 化しますか」と確認
- 賛成なら `gh issue create` で起票し、Toolbar には `reply_to_toolbar_thread` で Issue URL を返信

判定キーワード: 追加 / 増やして / 機能 / 新しい / 〜したい / 〜できるように

## (4) バグ報告 — 再現確認後に修正

例:
- 「クリックしても反応しない」「ページが真っ白」「エラーが出る」「データが表示されない」

対応:
- まず再現性を確認 (Preview URL を pnpm dev で再現できるか、コンソールエラーは出るか)
- 原因を特定してから修正案を提示
- 即対応するか、確認に時間がかかりそうなら別タスク化

判定キーワード: バグ / エラー / 動かない / 表示されない / 真っ白 / 反応しない / 失敗

## 判定優先度

複数該当する場合は (4) > (3) > (2) > (1) の順で優先。バグ報告は他より先に確認する。

## 自動修正の閾値

- 1 コメント = 1 ファイル & 5 行以内の変更で済む場合のみ自動修正
- それ以上の変更が見込まれる場合は「これは詳細修正に該当します。VS Code で対応するか、ユーザレビューを挟みましょう」と提案
