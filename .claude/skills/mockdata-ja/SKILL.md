# mockdata-ja

## このスキルが解決すること

`@faker-js/faker` を素で使うと:
- 同じ `id` でも参照先 (例: `user.companyId` と `company.id`) が一致しない
- KPI が「平均周辺に集中」して非現実的 (実際は対数正規 / Pareto に近い)
- 時系列が連続しない (日次データなのに穴あき)
- 業界固有用語が無い (医療なら ICD-10、金融なら証券コード)

このスキルは上記を満たすパターンを `lib/mock/<domain>/` に生成する。

## 起動方法

自律起動。「サンプルデータ作って」「日本語のダミー」「KPI データ」など。

## 業界テンプレ

- **EC**: order / product / customer / address (郵便番号→都道府県整合)
- **金融**: 証券コード (4 桁) / 銘柄名 / 価格時系列 / 取引量
- **保険**: 契約者 / 契約 / 給付 (傷病コード ICD-10)
- **医療**: 患者 / 受診 / 処方 (病名・薬剤)
- **小売**: 店舗 / 商品 / 売上 (時系列連続)
- **ヘルスケア**: ペルソナ / 食事 / 運動 (年齢層別 BMI 分布)

## 生成物

```
lib/mock/<domain>/
  ├── types.ts        — TypeScript 型定義
  ├── factories.ts    — make<Entity>() ファクトリ関数 (faker ja で生成)
  ├── distributions.ts— 対数正規 / Pareto / 時系列のヘルパ
  └── seed.json       — 任意で固定 seed の JSON (commit 可)
```

## 注意

- 実在ドメイン (`example.com` 以外) / 実在電話番号 / 実在郵便番号を**そのまま使わない**
  - 「郵便番号→都道府県整合」と両立させるには、**都道府県に対応する実在の上 3 桁帯 + 下 4 桁を架空値**にする (例: 東京都なら `100-9xxx` のように下 4 桁をランダム生成)。電話番号も同様に市外局番だけ実在帯を使い、加入者番号は架空値にする
- 実在クライアントのロゴ・商標は組み込まない
- 個人情報を含むデータを commit しない (固定 seed JSON でも要確認)
