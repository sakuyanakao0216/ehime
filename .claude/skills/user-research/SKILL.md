# user-research

## このスキルが解決すること

「ユーザーが欲しいと言ったから作った → 誰も使わなかった」を防ぐ。**作る前に、思い込み(仮説)を実ユーザーの言葉で裏取りする**。

1. **調査計画**: 何を確かめたいか(仮説) → 誰に・どの方法で・何を聞くか
2. **誘導しない問い**: 「使いますか?」ではなく「最近◯◯したのはいつ?」で過去の事実を引き出す
3. **インサイト整理**: 発言を「事実 / 解釈 / インサイト」に切り分け、Job Story 化

## 起動方法

### slash command
`/user-research [plan|interview|jtbd]` で起動。

### 自律起動
「ユーザー調査したい」「インタビュー設計して」「JTBD でまとめて」「ヒアリングの質問作って」などで自動起動。

## 進め方

ユーザーが「docs/discovery/user-research.md にまとめて」など成果物作成を明示している場合は、追加質問で止めず、入力仮説と既存ドキュメントから不足分を仮説として補い、必ず `docs/discovery/user-research.md` を作成する。長くなりすぎる場合も、**調査計画** / **誘導しない質問** / **インサイト** / **Job Story** を優先して 1 ファイルに収める。

### 1. 調査計画 (docs/discovery/user-research.md)

`idea-framing` の仮説 / 不確実性 TOP3 を入力に、何を検証するか先に決める。テンプレは [interview-guide.md](./references/interview-guide.md)。

```markdown
| 検証したい仮説 | 対象(誰) | 方法 | 主な問い |
|---|---|---|---|
| 〇〇に毎日困っている | 想定ペルソナ 3〜5名 | 1on1 インタビュー | 最近〇〇したのはいつ? その時どうした? |
```

### 2. インタビュー (誘導しない問い)

- **過去の具体行動**を聞く(「いつ / どこで / 何を / どうした」)。仮定の質問(「あったら使う?」)は信用しない
- 1 問投げたら**沈黙を許容**(Naoya 3 原則: 相手のペースを奪わない)
- 「なぜ?」を 2〜3 回掘って動機(Job)に到達する

### 3. インサイト → JTBD

発言を **事実 / 解釈 / インサイト**に切り分け、Job Story に変換。雛形は [jtbd-template.md](./references/jtbd-template.md)。

```
[状況] のとき、[動機] したい。なぜなら [期待する成果] だから。
```

## やってはいけないこと

- **誘導質問**(「便利だと思いませんか?」)→ 過去の事実を聞く形に直す
- 発言を**そのまま要件化**(言葉 ≠ 本当のニーズ)→ Job(動機)に翻訳する
- N=1 の声を全体の総意と扱う → 何件で何が言えたかを明記する

## 周辺

- `idea-framing`: 検証する仮説・不確実性 TOP3 の供給元
- `target-definition`: インサイトを基にセグメント/ペルソナを確定
- `competitive-analysis`: 「今どう解決しているか(代替手段)」の発言が競合の入力になる
- `spec-writer`: 裏取りした Job を PRD の要件に落とす
