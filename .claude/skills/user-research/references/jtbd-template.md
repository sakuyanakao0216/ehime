# JTBD / インサイト整理テンプレ

発言は「事実」と「解釈」を混ぜがち。切り分けてから Job(片付けたい用事)に翻訳する。

## インサイト整理表

発言ログ 1 行ごとに分解する。

```markdown
| 発言(生の言葉) | 事実(実際にした行動) | 解釈(なぜそうした) | インサイト(設計に効く気づき) |
|---|---|---|---|
| 「Excel で毎回作り直してる」 | 月次でテンプレを手コピー | 標準フォームが無く各自流用 | 共有テンプレの不在がムダの根 |
```

- **事実**: 観測できる行動・回数・道具。意見は入れない
- **解釈**: その行動の理由(仮説)。事実と区別する
- **インサイト**: 「だから何を作るべきか」に効く気づき。N と一緒に書く(例: 5人中4人)

## Job Story 雛形

機能ではなく**状況・動機・成果**で書く。

```
[状況] のとき、
[動機] したい。
なぜなら [期待する成果] だから。
```

例:
```
月初のレポート作成のとき、
前月のテンプレをすぐ再利用したい。
なぜなら毎回ゼロから作る時間を無くしたいから。
```

## まとめ(docs/discovery/user-research.md に転記)

```markdown
## 主要インサイト(優先順)
1. {インサイト} — 根拠: {N=◯, 代表発言}
2. ...

## Job Story
- {状況}のとき、{動機}したい。なぜなら{成果}だから。

## 確からしさ
- 確かめられたこと / まだ仮説のこと を分けて記載
```

## アンチパターン

- 解釈を事実として扱う(「不便そう」は事実ではない)
- 1 人の強い意見を全体傾向と書く → N を必ず添える
- 機能要望をそのまま Job にする(「ボタンが欲しい」は手段。背後の用事を書く)
