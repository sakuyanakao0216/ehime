# 競合比較表テンプレと評価軸候補

比較は**ユーザーが選ぶときに見る軸**で行う。自社が勝てる軸だけ並べない。

## 競合の3層で列挙

```markdown
| 区分 | サービス/手段 | 一言で | 主な利用者 |
|---|---|---|---|
| 直接 | {同じ用事×同じ手段} | | |
| 間接 | {同じ用事×別手段} | | |
| 代替 | {Excel / 手作業 / 何もしない} | | |
```

> 「代替=現状の凌ぎ方」が最強の競合であることが多い。`user-research` の「今どうしてる?」発言から拾う。

## 比較表

```markdown
| 評価軸(ユーザー視点) | 重要度 | 自社 | 競合A | 競合B | 代替 |
|---|---|---|---|---|---|
| 導入の手軽さ | 高 | ◎ | △ | ○ | ◎ |
| 価格 | 中 | ○ | △ | ◎ | ◎ |
| {ターゲット固有の軸} | 高 | ◎ | ○ | △ | × |
```

評価は ◎○△× で十分(プロト段階)。**重要度**列でターゲットが重視する軸を見分ける。

## 評価軸の候補(ターゲットに合わせて取捨選択)

| 種類 | 例 |
|---|---|
| 機能 | カバー範囲 / 自動化度 / 連携 |
| 体験 | 導入の手軽さ / 学習コスト / スマホ対応 |
| 経済 | 価格 / 無料枠 / 切替コスト |
| 信頼 | 実績 / セキュリティ / サポート |
| 適合 | ターゲットの用途への特化度 |

## まとめ(docs に転記)

```markdown
## 勝てる軸 / 負ける軸
- 勝てる: {軸} — 理由
- 負ける(許容): {軸} — なぜプロトでは許容できるか

## 空いている立ち位置
{誰も満たしていない 重要度高 の軸} → ここを狙う
```

## アンチパターン

- 自社有利な軸だけ選ぶ(重要度の低い軸で勝っても無意味)
- 機能数の合計で優劣を出す → 重要度で重み付けする
- 代替手段(Excel 等)を競合表に入れ忘れる
