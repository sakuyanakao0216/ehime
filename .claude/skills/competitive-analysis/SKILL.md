# competitive-analysis

## このスキルが解決すること

「競合いません」→ 実は皆 Excel や別アプリで凌いでいる、を防ぐ。**代替手段まで含めて競合を捉え、勝てる立ち位置を言語化**する。

1. **競合の列挙**: 直接 / 間接 / 代替手段(現状の凌ぎ方)を漏れなく
2. **比較 + ポジショニング**: ユーザーが選ぶときの軸で評価し、空いている立ち位置を見つける
3. **競争優位(MOAT)**: なぜ自社が勝てる/守れるかを言語化

## 起動方法

### slash command
`/competitor [map|matrix|moat]` で起動。

### 自律起動
「競合分析して」「競争優位は?」「差別化軸を整理」「ポジショニングしたい」などで自動起動。

## 進め方

### 0. 前提を固める(最初に必ず)

比較軸はターゲットと用途で変わる。**まず対象を置く** — `target-definition` の出力(優先セグメント・主要ユースケース)を読む。無ければ「仮ターゲット・仮ユースケース」を 1 行で明記してから進める。

### 1. 競合の列挙 (docs/discovery/competitive-analysis.md)

- **直接競合**: 同じ用事を同じ手段で解決
- **間接競合**: 別手段で同じ用事を解決
- **代替手段**: 現状の凌ぎ方(Excel / 手作業 / 何もしない)。`user-research` の「今どうしてる?」発言が源

### 2. 比較表 + ポジショニング

ユーザーが選ぶときの軸で評価。雛形・軸候補は [comparison-matrix.md](./references/comparison-matrix.md)。2 軸の地図で空白地帯を探すやり方は [positioning-moat.md](./references/positioning-moat.md)。

```markdown
| 評価軸(ユーザー視点) | 自社 | 競合A | 競合B | 代替(Excel) |
|---|---|---|---|---|
| {軸1} | ◎ | ○ | △ | △ |
```

### 3. 競争優位(MOAT)

「今は機能が違う」は優位ではない(すぐ真似される)。**守れる理由**(独自データ/ネットワーク効果/切替コスト等)を [positioning-moat.md](./references/positioning-moat.md) の類型で抽出。「なぜ今か」も言語化し idea-framing 問い4 へ。

## やってはいけないこと

- **「競合なし」で済ます**→ 代替手段(現状の凌ぎ方)を必ず挙げる
- 機能の多さで勝ち負けを決める → ユーザーが選ぶ軸で比較する
- 一時的な機能差を「優位」と書く → 真似されても残る MOAT を区別する
- 自社に都合よい軸だけ並べる → ターゲットが実際に重視する軸を使う

## 周辺

- `target-definition`: 比較軸の前提(対象・用途)の供給元。**先に通すのが望ましい**
- `user-research`: 代替手段(今どう凌いでいるか)の一次情報
- `idea-framing`: 問い4「新規性・なぜ今か」にここの結論を入れる
- `pitch-review`: 「競合との差別化軸」レビューの裏付けになる
