# 指標パターンとアンチパターン

NSM とツリーを組むときの定番フレーム。プロダクトの型に合うものを選ぶ。

## North Star Metric の選び方

良い NSM の条件:
- **価値の代理**: ユーザーが得る価値と相関する(売上の代理ではない)
- **動かせる**: 施策で短期に動く
- **偽装できない**: 数を盛っても意味が出ない(累計登録より「使った人数」)

例:
| プロダクト型 | NSM 例 |
|---|---|
| 作成系 | 週次アクティブ作成者数 |
| マーケット | 成約数 / GMV |
| メディア | 週次の意味ある閲覧時間 |
| SaaS 業務 | 週次アクティブチーム数 |

## AARRR(海賊指標 / ファネル型)

獲得 → 活性化 → 継続 → 紹介 → 収益。各段で 1 指標。

```
Acquisition(登録率) → Activation(初回価値到達) →
Retention(継続率) → Referral(招待) → Revenue(課金率)
```

→ どの段が一番漏れているかを見つけ、入力指標に落とす。

## HEART(体験品質型)

Happiness / Engagement / Adoption / Retention / Task success。
体験の質を測りたいときに AARRR と併用。

## ガードレール指標

NSM を追う裏で**悪化させてはいけない**もの。最低 1〜2 個置く。
- 解約率 / 直帰率 / サポート問い合わせ数
- 1 ユーザー当たりコスト(AI 利用ならトークンコスト → cost-guard)
- エラー率 / レイテンシ

## アンチパターン

- **虚栄指標(vanity metric)**: 累計登録数・総 PV。増え続けるだけで意思決定に使えない
- **指標過多**: KPI を 10 個並べる → NSM 1 + 主要数個に絞る
- **計測不能な指標**: 「満足度」など測り方未定のまま置く → 代理指標+計測方法をセットで
- **ガードレール無し**: 片方を上げて全体が悪化(例: 通知連打で DAU↑ 解約↑)

## プロト段階の割り切り

- 厳密な統計検定より「方向が見えるか」(`experiment-plan` と同じ思想)
- 基準線が無ければ「最初の 1〜2 週で取る」と決めて先に進む
