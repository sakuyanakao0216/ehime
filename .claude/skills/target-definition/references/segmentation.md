# セグメンテーション軸と優先度マトリクス

「全員」を狙うと誰にも刺さらない。意味のある軸で切り、最初の一群を 1 つ選ぶ。

## セグメント軸の候補

ひとつ選ぶのではなく、2〜3 軸を掛け合わせて「意味のある塊」を作る。

| 軸の種類 | 例 |
|---|---|
| 属性 | 業種 / 職種 / 企業規模 / 年代 |
| 行動 | 利用頻度 / 既存ツールの有無 / 自作で凌いでいる |
| 状況(JTBD) | どんな場面でその用事が発生するか |
| 痛みの強さ | 今すぐ解決したい / あれば嬉しい程度 |

> 良いセグメントの条件: **群の中は似ていて、群の間は違う**。そして到達手段がある。

## 優先度マトリクス(最初の一群を選ぶ)

```markdown
| セグメント | 規模 | 痛みの強さ | 到達可能性 | 自社との相性 | 判定 |
|---|---|---|---|---|---|
| A | 中 | 高 | 高 | 高 | ◎ 最初に狙う |
| B | 大 | 中 | 低 | 中 | △ 後で |
| C | 小 | 高 | 高 | 低 | ○ 検証用 |
```

評価のコツ:
- **痛みの強さ**を最優先(強い痛み = 多少粗くても使われる)
- **到達可能性**で現実性を見る(届かない大市場は今は罠)
- **規模**は「最初の 100 人が取れるか」程度で十分(プロト段階)

## アウトプット(docs/discovery/target-definition.md に転記)

```markdown
## 最初に狙うセグメント
{セグメント名}。理由: 痛みが{強い}・{到達手段}で届く・規模{十分}。

## 狙う順序
1. {A} → 2. {B} → 3. {C}（なぜこの順かを 1 行で）
```

## アンチパターン

- 軸が「年齢」だけ等、行動/痛みと無関係 → 設計判断に効く軸にする
- セグメントを切ったのに全部やる → 最初の 1 つに絞る
- 規模の大きさだけで選ぶ → 到達可能性と痛みを必ず併記
