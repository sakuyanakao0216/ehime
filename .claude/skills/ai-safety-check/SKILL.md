# ai-safety-check

## このスキルが解決すること

AI 機能は「動く」と「安全に出せる」が別問題。ピッチや公開の前に、出してはいけないもの・送ってはいけないものを点検する。

1. **不適切/有害出力**: モデル出力をそのまま見せて炎上しないか
2. **個人情報(PII)**: 入力/出力に PII が混じる経路はないか
3. **ハルシネーション**: 事実性が要る箇所で根拠なく断定していないか
4. **外部送信データ**: モデル/プロバイダに送るデータは妥当か（PII/機密を送っていないか）

## 起動方法

### slash command
`/ai-safety [output|pii|hallucination|egress]` で起動。

### 自律起動
「この AI 機能、安全性を確認して」「ハルシネーション対策」「PII を送ってないか」などで自動起動。

## 点検観点（[safety-checklist.md](./references/safety-checklist.md)）

| 観点 | 確認 | 対策の方向 |
|---|---|---|
| 不適切出力 | 有害/差別/逸脱の可能性 | システムプロンプト制約 + 出力フィルタ + 人手確認 |
| PII | 入出力に氏名/連絡先/ID | 入力前マスキング / 出力サニタイズ（→ privacy-check） |
| ハルシネーション | 事実性が要る応答 | RAG で grounding / 「分からない」を許容 / 出典提示 |
| 外部送信 | プロバイダに送る内容 | 機密/PII を送らない / 送信前マスキング / ログに残さない |

## ai-feature 実装ガードの確認

`ai-feature` のセキュリティ節（システムプロンプト末尾のインジェクションガード文 / 入力長制限）が入っているかも併せて確認する。未実装なら指摘。

## やってはいけないこと

- モデル出力を無検証で `dangerouslySetInnerHTML` する
- PII/機密をプロンプトやログにそのまま載せる
- 「対策済み」を主観で済ませる（観点ごとに根拠を残す）

## 周辺

- `ai-feature`: 点検対象（実装ガードの正）
- `ai-eval`: 安全性を評価項目として組み込む
- `privacy-check`: データの保存/ログ/削除/保存期間（こちらはガバナンス全般）
