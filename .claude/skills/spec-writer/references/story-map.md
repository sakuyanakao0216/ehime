# ユーザーストーリーマップ

`docs/specs/story-map.md`。横軸＝ユーザーの活動の流れ、縦軸＝優先度（上＝MVP）。

```markdown
# Story Map: <プロダクト名>

## バックボーン（ユーザー活動の流れ）
| サインアップ | 探す | 作る | 共有する | 振り返る |
|---|---|---|---|---|

## ストーリー（活動ごとに縦に並べる。上ほど優先）
### サインアップ
- [MVP] ユーザーとして、メールで登録できる
- [MVP] ユーザーとして、Google でログインできる
- [R2]  ユーザーとして、プロフィール画像を設定できる

### 探す
- [MVP] ユーザーとして、一覧を見られる
- [R2]  ユーザーとして、キーワードで絞り込める

## リリース単位
| リリース | 含むストーリー | 目的 |
|---|---|---|
| MVP（ピッチ用） | 上記 [MVP] | デモで主導線が通る |
| R2 | [R2] | … |
```

## 優先度の付け方

- 形式: `[MVP]` / `[R2]` / `[R3]` をストーリー先頭に
- MVP は「ピッチで主導線が 1 本通る」最小に絞る（欲張らない）
- PRD の機能要件 `F-x` と相互参照できるよう ID を併記してもよい

## 関連

- MVP の主導線は `app-flow-designer` の主要ユースケースと一致させる
- 各ストーリーの受入条件は `acceptance.md`（[prd-template.md](./prd-template.md) と同じ /spec で生成）
