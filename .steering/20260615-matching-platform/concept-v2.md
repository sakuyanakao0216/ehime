# 構想ブラッシュアップ v2 — 「スポーツ情報ハブ × 指導者候補の創出」両輪モデル

> 2026-06-15 追記。初期構想（運営者⇄指導者の広域マッチング）を、利用者起点で再設計したもの。
> 既存の v1（requirements / insights / competitive-analysis）は足元のマッチング(Wheel B)として包含する。

## 何を変えるのか（コアの転換）

- **旧**: 「教えたい人（指導者）」を集めてマッチングする。
  → 母集団が小さく、登録の動機が弱い（＝既存人材バンクが死蔵する根本原因）。
- **新**: **スポーツに接点のある大人**を、**愛媛スポーツ情報アプリ**として惹きつけて日常利用してもらい、
  ゆるい関わりを重ねて **指導者候補へ“育てる”**。母集団そのものを創出する。

## ターゲット利用者（指導者候補）の再定義

- ジムに通う社会人、スポーツ観戦好き、昔の競技経験者など、**いまもスポーツと接点がある大人**。
- 仮説: 「指導してください」と言われると気が引けるが、**何かのきっかけで“少し協力”する機会**があれば、
  実は練習サポートや指導ができる人が多く眠っている。
- だから必要なのは「指導者募集アプリ」ではなく、**その人たちが興味を持って登録し、見続けるアプリ**。

## 入口（フック）= 愛媛スポーツ情報のすべてが詰まったアプリ

- **今日 / 今月のスポーツイベント**が、**リスト＆地図**でまとまって見える。
  - プロ観戦（例: 愛媛FC / 愛媛オレンジバイキングス / 愛媛マンダリンパイレーツ など）
  - 地域のスポーツイベント・教室・大会
  - 学校のスポーツイベント（公開試合・体験会・合同練習）
- **割引・特典**を付けて「使わない理由がない」状態に（観戦チケット・ジム・用品など）。
- 観戦やジム通いのたびに使う → 自然に利用が習慣化。

## データ戦略（さりげなく集める）

- 登録時: スポーツ履歴（競技経験・レベル・観戦傾向）。
- アプリ内行動: 見たイベント / 行ったイベント / チェックイン / お気に入り種目 / 地域。
- → **「好き・得意なスポーツ」プロファイル**を形成し、**指導ポテンシャル**を推定する。
- 注意: 個人情報・行動データは目的明示と最小収集（privacy-check を後で通す）。

## 両輪モデル（このアプリの肝）

### Wheel A — 中長期: 関わりの階段で「指導者候補」を創出
1. スポーツ情報ハブで集客 → 嗜好・行動データ。
2. **AI が「つながりイベント」を企画・マッチング**（大人 × 学生 × ときにプロ）。
   - 例: 「週末・松山・バスケ観戦好きの社会人 × 中学バスケ部の体験会サポート」。
3. ゆるい関わりを、いろんな種目で**定期的に**実施 → リレーション構築。
4. **関わりの階段**を一段ずつ上げる:
   `観る → イベント参加 → ちょい手伝い → 継続サポート → 指導者`
5. これにより、中長期で関わるポテンシャル人材を増やす。**ここがAIの主戦場**（人・場所・イベントの組成）。

### Wheel B — 足元: いまのニーズを広域でマッチング（v1 を包含）
- 学校・クラブが「この種目をやりたいが集まらない / 経験者がいない」をリクエスト。
- **指導者候補リスト**（Wheel A で育った人 ＋ 既存の指導者）から、**複数拠点をまとめて広域で**つなぐ。
- 一校では成り立たない活動を、近隣校合同＋広域指導者で実現する。

## AI の位置づけ（明確化）

1. **つながりイベントの自動企画**: 嗜好データ × 学校ニーズ × 地域 → 「誰を・どこで・どの学校と」を組成。
2. **関わりの次の一歩レコメンド**: 各ユーザーに階段を一段上げる提案（観戦→体験会サポート 等）。
3. **足元マッチング**: ニーズ × 候補（既存コア）。

## 情報アーキテクチャ（新）

1. **ホーム / イベント**: 今日・今月のスポーツイベント（リスト＆地図 / 種目・エリア・カテゴリで絞る / 割引バッジ）。
2. **マイスポーツ**: 嗜好プロファイル、お気に入り種目、行ったイベント、**関わりの階段（レベル）**。
3. **つながる（Wheel A）**: AI が提案する「つながりイベント」「ちょい手伝い募集」。
4. **ささえる / リクエスト（Wheel B）**: 学校のニーズ一覧 → 応募・マッチング（運営者はリクエスト投稿）。

## KPI（仮）

- MAU / イベント閲覧・チェックイン数（フックが効いているか）。
- 嗜好プロファイル形成率。
- つながりイベント参加者数 → **継続関与率（階段を上がった率）**。
- 足元マッチ成立数（Wheel B）。

## 段階リリースの考え方

- フェーズ1（フック確立）: イベント情報ハブ＋お気に入り＋割引で「使われるアプリ」に。
- フェーズ2（候補創出）: 行動データ → AI つながりイベント → 関わりの階段。
- フェーズ3（足元実装）: 学校リクエスト × 候補の広域マッチング（v1）。
- 3つは並行しうるが、**フック（フェーズ1）が母集団の前提**なので最優先。
