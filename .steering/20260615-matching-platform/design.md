## 画面構成

| ルート | 視点 | 内容 |
|---|---|---|
| `/` | 共通 | ピッチ用トップ。課題（200減・偏在）→解決→KPI→活性化フィード→運営者/指導者導線 |
| `/operator` | 運営者 | ダッシュボード：自校の募集、AI推薦候補（スコア＋理由＋信頼レイヤー）、地域メーター |
| `/operator/recruit/new` | 運営者 | 募集作成フォーム → 送信で AI 推薦結果へ |
| `/instructors` | 共通 | 指導者一覧。種目・地域・オンライン可フィルタ。信頼レイヤー表示 |
| `/instructor` | 指導者 | マイページ：プロフィール、マッチする募集、研修受講、感謝の声、貢献バッジ |

共通要素: ヘッダー（ブランド＋視点切替）、アクティビティフィード、地域盛り上がりメーター。

## データモデル（lib/mock）

- `Region`: 東予 / 中予 / 南予
- `City`: 愛媛の市町（地域区分付き）
- `Activity`: 種目（運動部/文化部、アイコン）
- `Instructor`: 氏名/居住市町/専門種目/資格/研修修了/実績年数/オンライン可/空き時間/感謝の声/貢献バッジ/自己紹介
- `Recruitment`: 学校・クラブ/市町/種目/必要条件（曜日・オンライン可否・レベル）/緊急度/背景
- `ActivityFeedItem`: 種別（match/thanks/training/join）/本文/地域/日時
- `RegionStat`: 地域別の募集数・指導者数・充足率（メーター用）

## AI 設計（コア機能 / ai-feature 流儀）

- ルート: `POST /api/match`
- 入力: 募集条件（種目・市町・曜日・オンライン可否・求めるレベル/背景）
- 処理: `lib/ai.ts` の `model` ＋ AI SDK `generateObject`（Zod スキーマで構造化出力）
  - 候補（モック指導者プール）を文脈として渡し、各候補の **matchScore(0-100)** と
    **reason（なぜ合うか・日本語）** と **highlights（決め手タグ）** を返す
  - `logAiUsage({ feature: 'match' })` で利用量記録
- フォールバック: API キー未設定/失敗時は、ローカルのスコアリング関数（種目一致・地域近接・
  オンライン可否・空き時間・研修済み加点）で必ず結果を返す（プロトのデモが鍵に依存しない）

## 活性化 UI

- **アクティビティフィード**: 県内のマッチ・感謝・研修修了・新規参加がリアルタイム風に流れる
- **地域盛り上がりメーター**: 東予/中予/南予の充足率を Progress で可視化。空白地域に注意色
- **マッチ成立演出**: 推薦候補に「依頼する」→ 成立トースト/祝祭表現
- **貢献バッジ**: 指導者の研修修了・感謝数・関わった学校数をバッジ化

## 非機能 / プロト割り切り

- 認証なし（視点切替はヘッダーのリンク）。データは `lib/mock` の静的＋少量の擬似乱数。
- `next.config.mjs` の ignoreBuildErrors / images.unoptimized はテンプレ既定のまま。
